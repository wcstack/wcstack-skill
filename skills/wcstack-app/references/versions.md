# A page pinned to an older 4.x release

`SKILL.md` and the other references describe the release named in `SKILL.md`'s `wcstack-version`. Read this only when the page pins an older 4.x release on its wcstack lines (`https://esm.run/@wcstack/state@4.9.0/auto`). For 3.x code, read `state-binding.md` §16 instead.

- **Keep the lint at the page's version** (`npx @wcstack/lint@4.9.0`). An older lint reports newer syntax as an error, and a newer lint reports rules the page's runtime does not follow.
- **Warnings arrive release by release.** The diagnostics warnings and lint rules this skill names may not exist at the page's version: silence there proves nothing. The checks themselves — the lint loop, the browser — still apply.
- **Upgrading instead**: `docs/upgrading-4x.md` in the wcstack repo lists, per release, what changes and which workarounds it makes unnecessary. Change only the versions, run the checks, then remove the workarounds one at a time — a workaround kept after its fix can fight it.

## What a pinned page writes differently

Each row applies to every release up to and including the one named. The workarounds are the ones the seam apps used, recorded in `docs/upgrading-4x.md`.

| Pinned at or below | What differs | Write instead |
|---|---|---|
| 4.28 | The lint reads no component: a page's read of a getter a class component exports is reported `wcs/binding-path-missing`; a component's methods and template, a DCC's declarations and the members a page binds on it are not checked; a DCC's markup and the page's are checked against one set of keys | Declare the exported getters as optional keys in the JSDoc type of the page's data, and check them by hand after a rename; unit-test each part |
| 4.28 | `radio:` / `checkbox:` written before the binding that gives the control its value is not reported | Check the order by eye: the value first (`attr.value: .value; radio: theme`) |
| 4.27 | No loader for a DCC kept in a file; an eager key's loader is chosen by the key, never by the file's extension | A loader of the page's own that fetches the file and parses it with `setHTMLUnsafe()`, named in each eager key; or write the definition in every page |
| 4.27 | An element that writes when it is bound (`value#init=element:`) to a path under a volume whose file arrives after the root's throws `Path "…" does not exist`: the root fails and nothing is bound | Bind the element to a root key and copy it to and from the volume by `$watch` |
| 4.27 | A DCC's `$connectedCallback` sees the default, not the first value the page gives; an attribute on a DCC is ignored without a word; `#ro` on one mapped key does not hold for a component mounted inside | Derive from the input in a getter; bind every input; do not rely on `#ro` across two levels |
| 4.27 | A wrong name between a page and a mounted component is silent on both sides; a volume's mount path and a component writing its mounted tree can warn `[wcs/write-path-missing]` falsely | Unit-test the component with the page's data; ignore that message for a mount path |
| 4.27 | `mount()` (`@wcstack/testing`) never defines a DCC written in the HTML; `wcs-schema check` on a root with merged volumes always fails | Define the part by hand before `mount()`; run `check` for the volumes only |
| 4.26 | An `eventToken.*`, an output-property binding or a `bindNode` signal also hears a nested element's bubbling event of the same name, with the inner element's `detail` | Check `event.target` in the handler, or do not nest two elements of the same kind |
| 4.26 | A form the router draws before the root state loads can be submitted natively — a GET with the fields, a password too, in the URL — and text typed before binding is erased | Write `disabled` on the submit button in the markup and bind it (`disabled: sending`), so it is usable only once bound |
| 4.25 | Clearing `<wcs-sse>` / `<wcs-ws>`'s `url` leaves the connection open; `<wcs-sse>` does nothing when the page leaves | Call `close()` with clearing `url` (sign-out); close the stream in a `beforeunload` listener only on a page without a router (WebKit fires it on router navigations) |
| 4.25 | `<wcs-debounce>` / `<wcs-throttle>` `value` starts `undefined` and seeds the bound slot with it | Guard the slot's `$watch` against `undefined` |
| 4.25 | No Vite plugin; `wcs-tsc` checks an inline state as TypeScript (JSDoc ignored, a type annotation passes) | Mark inline scripts `vite-ignore` and emit the `src` state file yourself; write an inline state without annotations |
| 4.24 | The screen and sensor elements have no `supported` output, and `<wcs-permission>` no `unsupportedReason` | Detect the API yourself (`document.fullscreenEnabled`, `"share" in navigator`, `document.permissionsPolicy`) before offering the button |
| 4.24 | `<wcs-tilt>` sets `permissionState` to `"denied"` when an iPhone refused to ask (a call outside a tap), and has no `heading` | Read `"denied"` with a non-null `error` as "not asked yet" (`permissionState !== "granted"` shows the button); find north with a `deviceorientationabsolute` / `webkitCompassHeading` listener |
| 4.24 | `<wcs-accelerometer>` / `<wcs-gyroscope>` are `unsupported` where the browser has no sensor class (an iPhone, Firefox) | A `devicemotion` listener of the page's own, with `DeviceMotionEvent.requestPermission()` called from the tap |
| 4.24 | `<wcs-credential>` has no `preventSilentAccess` and does not build a `PasswordCredential`; `<wcs-contacts>` writes `value: []` when the picker is closed | Call `navigator.credentials.preventSilentAccess()` on sign-out and build `new PasswordCredential(…)` for `store()`; read an empty array as "closed" |
| 4.24 | `<wcs-ws>`'s `close` and `<wcs-idle>`'s `start` wired straight to a button (`onclick: $command.close`) take the event as their first argument and fail | Emit them from a state method with no arguments |
| 4.24 | `<wcs-fullscreen>` / `<wcs-pointer-lock>` / `<wcs-pip>` keep `active: true` after they leave the document | Write the flag back to `false` when the route that holds them is left |
| 4.24.1 | A route's static segment is a regular expression (`/v1.0` matches `/v1x0`), a path with characters outside ASCII matches no URL, and `params` arrive percent-encoded | Keep route paths to ASCII and avoid `.`, `+` and brackets (or write the path percent-encoded); decode a param by hand. From 4.24.2 params arrive decoded — decoding again throws for a value with a `%` |
| 4.23 | A button **beside** a `<wcs-link>` in a `for:` row runs no handler, or its neighbour's; `to: .href` (a property binding) leaves the `<a>` with no `href` | A plain `<a>` in the row in place of `<wcs-link>`; `attr.to: .href` |
| 4.23 | `<wcs-fetch>`'s `fetch` command ignores its arguments; `<wcs-infinite-scroll>` stops while its sentinel stays on screen after a short page | Write the url first and emit `fetch` from a `$watch` on it; give the target a static `url` for page 1, and make pages large enough to push the sentinel out of the window |
| 4.23 | `data-wcs` on `<body>` / `<html>` and an `on*:` on `<wcs-link>` do nothing, with no warning | The same on every version: bind on an element inside `<body>`, and put handlers inside or around the link |
| 4.23 | The lint reads only the first `@typedef` of a JSDoc block | One `@typedef` per block |
| 4.22 | No `forms` add-on: state writes into a field while it is composed with an IME, a value the browser fills without an `input` event (a password manager) never reaches state, and a reset blanks the fields while state keeps its values | Bind a field that normalizes what is typed one way and write it from a handler that skips `event.isComposing`; a `change` listener that copies the field into state; a `clear()` method that assigns state instead of `type="reset"` |
| 4.22 | An I/O element in a `for:` row that is reordered aborts its request (or restarts its timer) when the row moves | Do not reorder rows while a row's request is in flight |
| 4.21 | No relative paths in script (`this[".name"]`) and no accessor declared for several lists (`get "a.*.x,b.*.x"()`) | The same accessor body written once per list with full paths, repeated under a filtered copy (`get "shown.*.fullName"()` beside `get "users.*.fullName"()`) |
| 4.19 | Every `<wcs-state src>` naming one module gets the same state object (a DCC's or a component's instances share it); the number filters (`locale`, `currency`, `toFixed`, …) refuse an absent value | Export a factory and build each state in an inline module; `\|coalesce(0)` in front of `locale` where the value can be absent |
| 4.16 | A setter that writes its own path overflows the stack with a `RangeError` naming nothing; a setter whose getter does not read what it writes is not reported | The rules are the same (store under a key the getter reads); only the messages are missing |
| 4.15 | No `$update(path, indexes, fn)`; a `$setAll` mapper is not run at the row it writes | Read and write the row path: ``const p = `items.${i}.label`; this[p] = this[p] + " !!!";`` |
| 4.11 | `<wcs-link>` has no `query-keys`: over a paged list, a tab is current on page 1 only | Plain `<a>` tabs with `attr.aria-current:` from state |
| 4.10.1 | A `<wcs-link to="/notices">` (no query) is current on every query | Plain `<a>` with its own `aria-current` |
| 4.9 | A link to a bare fragment (`<a href="#main">`, a skip link) under `<base href>` goes to the home route; a `<wcs-link>` with a query is current everywhere; under `<wcs-view-transition>` a `$watch` runs before the transition's bindings; the date filters take no time zone | An `onclick#prevent:` handler that focuses `#main`; plain `<a>` with `attr.aria-current:` and `class.…:` bindings; navigation and focus moves in `$renderedCallback`; `Intl.DateTimeFormat(…, { timeZone })` in getters |
| 4.8 | `leaveConfirm` on `<wcs-router>` turns a boolean into the question's text (`confirm("false")`); `<wcs-upload>` sends no request header; `<wcs-sse>` stays closed after the browser gives up; `@wcstack/testing`'s `mount()` cannot load a `<wcs-state src>` | Bind a string or `null` (`get discardPrompt() { return this.dirty ? "…" : null; }`); `UploadCore` imported from the CDN and driven from state; a timer that reopens the stream on `errorInfo.recoverable === false`; a copy of the state in an inline script for the test |
| 4.7 | No `stale-after` on `<wcs-sse>` / `<wcs-ws>`; an open `<wcs-ws>` keeps the page out of the back/forward cache | A watchdog of the page's own (the time of the last message, a close and a reopen after a silence); close the socket in `pagehide`, open it in `pageshow` |
| 4.6 | The engine's errors reach `console.error` only, not `window`'s `error` event; a date filter refuses `null` | An `$errorCallback` that calls `reportError()`; an `if:` around a date binding whose value arrives later |
| 4.5 | `<wcs-storage>` has no `storage-key` (React / Vue keep `key`); an automatic `<wcs-upload>` drops `files` written before `url`; no `/auto` entry has a type | `el.key = …` through a ref; `url` before `files`; a declaration of your own (`declare module "@wcstack/*/auto";`) |
| 4.4 | A disconnect does not publish what it changes (a route left with `<wcs-camera>` in it still says the camera is on); a feature the page cannot use looks like the user's refusal | A `$watch` on `routeName` that writes `active` / `recording` back to `false`; read `document.permissionsPolicy` and `isSecureContext` yourself |
| 4.2 | No `data-wcs-ignore`: every `{{ }}`, `data-wcs` and comment binding in the page is read; `<wcs-fetch>` skips a url equal to the last one fetched even after an empty url in between | Never put markup you did not write into the page; `manual` on the read `<wcs-fetch>` and a `$watch` on its url that emits a `fetch` command |
| 4.1 | No date styles or `currency` on the filters | `Intl.DateTimeFormat` / `Intl.NumberFormat` formatters in getters |
| 4.0.4 | `$watch` does not fire for a value the router or an open stream already has at load; no `leaveConfirm`; `<wcs-link>` has no `match="prefix"`; `value:` on `<wcs-fetch-header>` sends an empty header | The same work in `$connectedCallback`; a `navigate` listener of the page's own; the section link's mark computed by the page; `attr.value:` on the header |
