# wcs-* I/O nodes inside a React / Vue / Svelte / Solid app

Read this before putting a `wcs-*` element in a framework's component. Nothing here uses `data-wcs` or `@wcstack/state`: every I/O node implements wc-bindable, so a thin adapter (`@wc-bindable/react`, `/vue`, `/svelte`, `/solid`, …) maps an element's outputs into framework state with no per-element glue (`docs/framework-adapter-integration.md` in the wcstack repo). Worked apps: `examples/fw-inventory` (a React 19 back office and a Vue 3 panel, with an e2e spec) and `examples/websocket-chat` (React 19 and Vue 3 against the same server as the vanilla / state / signals variants).

The lint does not read a framework's components (it lists them under `not read:`): verify the app in the browser.

## The rules

1. **Use `@wc-bindable/*` 0.9 or later, and import the definition before the app renders anyway.** The adapters wait for a late definition (`syncOn: "define"`, their default) and bind when it lands; 0.8 and earlier checked once on mount and never retried, so an element that upgraded later stayed unbound with no error. A static import at the entry (`import "@wcstack/websocket/auto";` in `main.tsx`) works with every version. With a 0.8 adapter and a definition that arrives late (autoloader, CDN tag, code-split), gate the mount on `customElements.whenDefined("wcs-ws")`. A `syncOn` of your own replaces the default — keep `"define"` in it. `connectedCallbackPromise` covers connection, not definition.
2. **Pass object-valued inputs as properties, not attributes.** Attributes hold only strings, and several frameworks fall back to attributes when the property is not on the element yet, which stringifies the payload. Use `.prop` (Vue), `prop:` (Solid), `.prop=` (Lit), or assign through a ref. An element that finds an object written as an attribute when it connects (`files="[object File]"`) warns `[wcs/input-as-attribute]`. Assign a **new** object or array to change one: `files.push(f)` writes nothing a framework sees, and `body` / `files` are used up by each request.
3. **Pass deep plain copies of reactive store values.** Vue `reactive`, Svelte `$state`, Solid stores, MobX and Qwik `useStore` wrap objects in proxies, and a proxy cannot cross a structured-clone boundary — `<wcs-worker>` / `<wcs-broadcast>` report a `DataCloneError` into `error` instead of sending (and warn `[wcs/post-uncloneable]`). Vue's `toRaw()` unwraps **one level**: the rows of a reactive list are still proxies. Post `JSON.parse(JSON.stringify(value))` (Vue, Qwik) or `$state.snapshot()` (Svelte).
4. **Read `event` outputs off the element, not the adapter's values.** `message` on `<wcs-sse>` / `<wcs-ws>` / `<wcs-broadcast>` / `<wcs-worker>` is an occurrence: through `values` + `useEffect` / `watch`, events that arrive together reach the component as one, and an equal value as none. Listen with `addEventListener("wcs-sse:message", …)` on the element; keep the adapter for `connected` / `loading` / `error` / a fetched `value`.
5. **Hold the element yourself, and call commands.** React's `useWcBindable` returns a callback ref and no element: wrap it (`const ref = useCallback((n) => { el.current = n; bindRef(n); }, [bindRef])`). In Vue `<script setup>`, name the template ref statically — `const { ref: socket, values } = useWcBindable()` + `<wcs-ws ref="socket">`; a `:ref="ref"` binding is unwrapped to `null` and the adapter never binds, with no warning. From framework state, call the command (`el.fetch()`, `el.upload()`, `el.save()`) instead of driving `trigger`: the element resets `trigger`, the framework still holds `true`, and the second `true` is never written.
6. **Mind the names and the order a framework uses.** React and Vue keep `key`: write `<wcs-storage storage-key="…">` (`key=` in JSX or a Vue template stores nothing). Props are applied in the order written, before the element is in the document: write the input that is read first first (an automatic `<wcs-upload>` keeps `files` that come before `url`). To follow another tab's `<wcs-storage>` from React, listen to `wcs-storage:value-changed` and skip the events your own save dispatches — applying the adapter's `value` back undoes the typing in between and loops. A component whose `key` changes remounts its I/O nodes (a new SSE connection each time); removing a prop does not close a stream — call `close()`.

## Around the rules

- Live handles such as `<wcs-camera>`'s `MediaStream` are not snapshot state — take them off the element's event via a ref.
- **Event names with a colon** (`wcs-fetch:response`): Angular templates cannot bind them; in React 19 JSX it depends on the transform (Babel refuses a namespaced name), and where it compiles the name is case-sensitive — `onwcs-fetch:response` works, `onWcs-fetch:response` never fires. `addEventListener` / `Renderer2.listen` is the portable path.
- **TypeScript**: every `/auto` entry has a type, so `import("@wcstack/sse/auto")` type-checks. JSX declarations for the tags are written by hand (`declare module "react" { namespace JSX { interface IntrinsicElements { "wcs-sse": … } } }`).
- **Vite's dev proxy**: end the response on a proxy error (`configure: (p) => p.on("error", (_e, _q, res) => res.destroy())`), or an SSE stream stays "connected" after the server restarts.
